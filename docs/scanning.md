# 目標搜尋介面

雙擊 `Start.bat` → 選「傳送與辨識」→ 啟動 → 在新視窗按「開始搜尋」。控制台會先建立裝置連線。也可在已啟動 tunneld 的管理員終端機執行 `main.py`；它現在會開啟介面，不會立即開始傳送。

## 地圖與截圖

- 藍色標點：目前正在搜尋／截圖的指定座標。
- 橘色標點：最後送給裝置的定位。提前傳送模式可能已經是下一點；與搜尋點相同時只顯示藍色標記。
- 綠色標點：本次找到目標的位置，點選會連動下方清單與命中圖片。
- 目前截圖：最近一次擷取的完整畫面，並非即時串流。會顯示座標、序號和截圖時間，即使未命中仍可預覽。
- 命中截圖：第一次命中會自動顯示；之後保留你的選擇。點清單或地圖標記可換圖，雙擊預覽或按「開啟原始截圖」可開啟原圖。

兩個圖片區會等比例縮放，不裁切內容。上下區域可拖曳分隔線調整。取消「跟隨搜尋位置」後，可自由瀏覽命中標記。地圖僅顯示本次搜尋命中；歷史圖片可由「結果資料夾」開啟。極區緯度超出 ±85 時，地圖標記限於可顯示範圍，結果中的座標仍保留原值。

## 截圖時序

預設 **提前傳送（原流程）**：第一點等待首次載入時間，之後先傳送下一點，再等待並截圖，圖片記在當前搜尋點。此方式沿用原本對遊戲載入延遲的假設。

可選 **逐點等待後截圖**：先傳送當前搜尋點，等待截圖時間、擷取後才會處理下一點。第一點另加首次等待。這種模式避免提前傳送，但仍須設定足夠的載入時間。

兩種模式的標記都是搜尋指定座標，並非手機實際 GPS 回讀；畫面位置是否已更新仍需要依實機載入速度確認。辨識沿用 `vision.py` 的範本比對與差異門檻。

## 進度與停止

可設定起始點（從 1 開始）、最多掃描點數、首次等待、截圖等待、最短週期與辨識門檻。執行期間鎖定設定，停止後可調整。

顯示已掃描點數、命中數、錯誤數、待辨識張數、已用時間及掃描剩餘估算。已掃描包含截圖失敗的嘗試；時間依本次實際平均速度估算，不包含最後的辨識收尾。

「停止並還原定位」會中斷等待，在目前裝置指令結束後嘗試還原定位，再完成已擷取圖片的辨識與存檔。截圖指令最長等待 15 秒、還原最長等待 20 秒，辨識時間依圖片與範本數量而異。

停止後可按「從中斷點繼續」，沿用本次設定與剩餘範圍，開啟新的搜尋紀錄。已嘗試但截圖失敗的點不會自動重試，可手動填入起始點重新搜尋。新搜尋會清空地圖與清單，已儲存的檔案會保留。

正常關閉搜尋視窗也會先停止與收尾。控制台外層的停止按鈕仍屬強制停止，可能中斷尚未完成的辨識；日常使用請優先按搜尋視窗內的停止。

## 結果存檔

- `found_targets/`：命中原始截圖，檔名包含目標、座標、本次識別碼與座標序號，不會與之前的結果重名。
- `scan_sessions/<本次識別碼>/latest.png`：本次最後一張截圖。
- 同資料夾的 `config.json`：本次設定。
- 同資料夾的 `results.jsonl`：逐張完成的辨識結果，包括命中、未命中及辨識錯誤。截圖失敗會顯示在介面紀錄。
- 辨識失敗的截圖會保留供檢查；正常未命中截圖刪除，但目前預覽及 `latest.png` 保留。

選取結果可複製座標，或將本次命中清單匯出為 CSV，包含目標、座標、時間、圖片路徑與時序模式。程式不會自動清除歷史搜尋資料夾。

## 驗證

`myenv\Scripts\python.exe -m unittest discover -s tests -v`

`myenv\Scripts\python.exe -m tests.check_scan_ui`

測試涵蓋兩種時序、停止／續掃位置、命中存檔、未命中預覽保留、截圖與辨識失敗、定位還原失敗及離線地圖／圖片元件。這些測試使用模擬裝置，不會傳送手機定位。
